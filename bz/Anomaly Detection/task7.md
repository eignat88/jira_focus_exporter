# Task 7

# Постановка задачи: агент-администратор проекта

## Цель

Создать агента-администратора проекта, который при каждом запуске анализирует рабочую папку проекта и формирует актуальное состояние: где сейчас находится проект, что уже сделано, что выполняется сейчас, что осталось сделать и какие задачи требуют внимания.

## Основная задача агента

Агент должен пройти по папке проекта, изучить структуру, документы, задачи, логи, результаты работы других агентов и сформировать единый управленческий отчёт по проекту.

Агент не должен выдумывать информацию. Если данных не хватает, он должен явно фиксировать это в отдельном разделе.

## Что агент должен анализировать

Агент должен проверить:

1. структуру папок проекта;
2. наличие документов с постановками задач;
3. наличие готовых результатов по задачам;
4. наличие промежуточных файлов;
5. наличие логов работы агентов;
6. актуальные README, task-файлы, отчёты, реестры;
7. незавершённые или противоречивые задачи;
8. зависимости между задачами;
9. файлы, которые требуют проверки человеком.

## Что агент должен сформировать

После анализа агент должен создать или обновить следующие файлы:

### 1. `project_status.md`

Файл с текущим состоянием проекта.

Структура:

```md
# Текущее состояние проекта

## Краткое резюме
- Где сейчас находится проект
- Общий статус
- Основные риски

## Что уже сделано
...

## Что выполняется сейчас
...

## Что осталось сделать
...

## Блокеры
...

## Что требует решения человека
...

## Недостающая информация
...

## Рекомендации по следующим шагам
...
```

### 2. `task_register.md`

Реестр задач и подзадач.

Структура:

```md
# Реестр задач проекта

| ID | Задача | Статус | Исполнитель/агент | Приоритет | Зависимости | Комментарий |
|---|---|---|---|---|---|---|
| T1 | ... | Не начато / В работе / Готово / Требует проверки | ... | Высокий | ... | ... |
```

### 3. `gantt.md`

Диаграмма Ганта в формате Mermaid.

Пример:

````md
# Диаграмма Ганта

```mermaid
gantt
    title План работ по проекту
    dateFormat  YYYY-MM-DD
    section Анализ
    Анализ папки проекта           :done,    t1, 2026-07-08, 1d
    Формирование реестра задач     :active,  t2, 2026-07-08, 1d

    section Доработка документов
    Раздел AS IS                   :         t3, 2026-07-09, 2d
    Раздел TO BE                   :         t4, 2026-07-11, 2d

    section Проверка
    Финальная вычитка              :         t5, 2026-07-13, 1d
````

````

Диаграмма должна обновляться при каждом запуске агента.

### 4. `admin_log.md`

Журнал запусков агента.

Структура:

```md
# Журнал агента-администратора

## Запуск от YYYY-MM-DD HH:MM

### Что было проверено
...

### Что изменилось с прошлого запуска
...

### Какие файлы обновлены
...

### Новые риски
...

### Следующие действия
...
````

## Логика работы агента при запуске

При каждом запуске агент должен:

1. просканировать папку проекта;
2. определить ключевые документы и файлы задач;
3. сравнить текущее состояние с предыдущим запуском, если есть `admin_log.md`;
4. определить выполненные, текущие и оставшиеся задачи;
5. обновить `project_status.md`;
6. обновить `task_register.md`;
7. обновить `gantt.md`;
8. добавить запись в `admin_log.md`;
9. отдельно вывести список вопросов, которые требуют решения человека.

## Статусы задач

Использовать только следующие статусы:

* `Не начато`
* `В работе`
* `Готово`
* `Требует проверки`
* `Заблокировано`
* `Отложено`

## Требования к качеству

Агент должен:

* не удалять существующие данные без необходимости;
* не переписывать вручную добавленные комментарии без причины;
* не выдумывать сроки, если они не указаны;
* явно помечать предположения;
* фиксировать источники, из каких файлов сделан вывод;
* отделять факты от предположений;
* выделять блокеры и риски;
* предлагать следующий практический шаг.

## Отдельный раздел: недостающая информация

Если агент не может определить статус задачи, сроки, зависимости или результат, он должен добавить это в раздел:

```md
## Недостающая информация

| Что неизвестно | Где требуется уточнение | Почему важно |
|---|---|---|
| ... | ... | ... |
```

## Итоговый результат работы агента

После запуска агент должен вывести краткий отчёт:

```md
# Итог запуска агента-администратора

## Обновлены файлы
- project_status.md
- task_register.md
- gantt.md
- admin_log.md

## Текущий статус проекта
...

## Ближайшие действия
1. ...
2. ...
3. ...

## Что требует решения человека
...
```

## Важно

Агент-администратор не выполняет задачи других агентов. Его задача — управлять состоянием проекта, фиксировать прогресс, выявлять пробелы и поддерживать актуальную картину проекта.
