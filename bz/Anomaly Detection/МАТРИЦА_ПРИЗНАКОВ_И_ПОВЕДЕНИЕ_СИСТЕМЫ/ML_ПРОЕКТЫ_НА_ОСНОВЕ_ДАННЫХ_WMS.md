## 2. Варианты ML-проектов

### 2.1. Предсказание проблемных КМ (Classification)

**Задача:** Предсказать, будет ли КМ проблемным ДО сканирования.

**Целевая переменная:** `IsProblemKM` (0/1)
- 1: КМ отсутствует, заблокирован, не введён в оборот, конкурентный
- 0: КМ прошёл все проверки

**Признаки (Features):**

| # | Признак | Тип | Источник |
|---|---------|-----|----------|
| 1 | `product_group_id` | Категориальный | InventTable → MPProductGroup |
| 2 | `is_osu` | Бинарный | InventTable.ALK_Volumetric |
| 3 | `is_markable` | Бинарный | InventTable.LFL_IsMarkableItem |
| 4 | `alk_scan_mc` | Бинарный | MPProductGroup.ALK_ScanMC |
| 5 | `enable_without_mc` | Бинарный | MPProductGroupFEACCMarkDates |
| 6 | `supplier_id` | Категориальный | LFL_MarkingCodeTable.ExtOwnerName |
| 7 | `is_competitor` | Бинарный | LFL_MarkingCodeTable.Competitor |
| 8 | `km_age_days` | Числовой | DATEDIFF(CreatedDateTime, NOW) |
| 9 | `historical_error_rate` | Числовой | COUNT(problematic) / COUNT(total) по товару |
| 10 | `day_of_week` | Категориальный | День недели |
| 11 | `hour_of_day` | Числовой | Час сканирования |
| 12 | `warehouse_load` | Числовой | Количество активных маршрутов на складе |
| 13 | `worker_experience` | Числовой | Среднее время обработки сотрудника |

**Модели:**
- **Baseline:** Logistic Regression
- **Основная:** LightGBM / CatBoost
- **Экспериментальная:** Neural Network (TabNet)

**Метрики:**
- Precision@K (top-10% самых вероятных проблемных КМ)
- Recall@K
- F1-score
- AUC-ROC

**Бизнес-эффект:**
- Заранее отложить проблемные товары
- Снизить простои на контроле на 20-30%
- Ускорить обработку заявок

**Время MVP:** 2-3 недели

### 2.2. Предсказание времени комплектации (Regression)

**Задача:** Предсказать время выполнения маршрута комплектации.

**Целевая переменная:** `DurationMinutes` (минуты)

**Признаки:**

| # | Признак | Тип | Источник |
|---|---------|-----|----------|
| 1 | `route_line_count` | Числовой | COUNT(WMS_PickingLineBuffer) |
| 2 | `total_qty` | Числовой | SUM(Qty) |
| 3 | `osu_items_pct` | Числовой | % товаров ОСУ в маршруте |
| 4 | `markable_items_pct` | Числовой | % маркируемых товаров |
| 5 | `competitor_items_pct` | Числовой | % товаров с конкуренцией MP |
| 6 | `worker_id` | Категориальный | WMSPickingRoute.operatorWorker |
| 7 | `worker_avg_time` | Числовой | Среднее время предыдущих маршрутов |
| 8 | `warehouse_load` | Числовой | Количество активных маршрутов |
| 9 | `hour_of_day` | Числовой | Время начала |
| 10 | `day_of_week` | Категориальный | День недели |
| 11 | `has_problem_km` | Бинарный | Наличие ProblemKM в маршруте |
| 12 | `pallet_type` | Категориальный | WMSPickingRoute.WMS_PickingPalletTypeId |

**Модели:**
- **Baseline:** Linear Regression
- **Основная:** XGBoost / Random Forest
- **Экспериментальная:** LSTM (если есть временные ряды)

**Метрики:**
- MAE (Mean Absolute Error)
- RMSE
- R²
- MAPE (Mean Absolute Percentage Error)

**Бизнес-эффект:**
- Планирование ресурсов
- Оптимальное распределение заданий
- Снижение простоя сотрудников

**Время MVP:** 2-3 недели

### 2.3. Обнаружение аномалий (Anomaly Detection)

**Задача:** Найти подозрительные паттерны сканирования.

**Типы аномалий:**

| # | Аномалия | Описание | Опасность |
|---|----------|----------|-----------|
| 1 | **Слишком быстрое сканирование** | Интервал < 2 сек между кодами | Мошенничество |
| 2 | **Много ошибок подряд** | > 5 ошибок подряд от сотрудника | Нарушение процесса |
| 3 | **Увеличение конкурентных КМ** | Рост > 30% за период | Проблемы с поставщиком |
| 4 | **Отсутствие сканирований** | Нет активности в рабочее время | Простой |
| 5 | **Несоответствие SSCC** | SSCC не найден в базе | Подделка |

**Признаки:**

| # | Признак | Тип | Источник |
|---|---------|-----|----------|
| 1 | `scan_interval` | Числовой | DATEDIFF(предыдущее, текущее сканирование) |
| 2 | `error_streak` | Числовой | Количество ошибок подряд |
| 3 | `scans_per_hour` | Числовой | Количество сканирований в час |
| 4 | `error_rate` | Числовой | Доля ошибок за смену |
| 5 | `competitor_ratio` | Числовой | Доля конкурентных КМ |
| 6 | `time_since_last_scan` | Числовой | Время с последнего сканирования |

**Модели:**
- **Isolation Forest** — для точечных аномалий
- **Local Outlier Factor (LOF)** — для локальных аномалий
- **Autoencoder** — для сложных паттернов
- **LSTM Autoencoder** — для временных аномалий

**Метрики:**
- Precision
- Recall
- F1-score
- False Positive Rate

**Бизнес-эффект:**
- Предотвращение мошенничества
- Контроль качества работы сотрудников
- Выявление проблем с поставщиками

**Время MVP:** 1-2 недели

### 2.4. Рекомендации по настройкам (Recommendation System)

**Задача:** Рекомендовать оптимальные настройки для новых товарных групп.

**Вход:** Характеристики ТГ

**Выход:** Рекомендации:

| Параметр | Тип вывода | Описание |
|----------|------------|----------|
| `ALK_ScanMC` | Бинарный | Обязательное сканирование КМ |
| `EnableWithoutMC` | Бинарный | Допуск ОСУ без КМ |
| `AllowPieceControl` | Числовой | Порог поштучного контроля |
| `RemarkingLocationId` | Категориальный | Ячейка пере-маркировки |
| `NoScanMC` | Бинарный | Отгрузка без КМ |

**Модели:**
- **Content-Based:** Похожие ТГ → похожие настройки
- **Collaborative Filtering:** ТГ с похожими товарами → похожие настройки
- **Multi-Output Classification:** Одна модель для всех параметров

**Метрики:**
- Accuracy (для бинарных параметров)
- RMSE (для числовых)
- Business Metric: Снижение ошибок после применения рекомендаций

**Бизнес-эффект:**
- Ускорение внедрения новых ТГ
- Снижение ошибок на 15-25%
- Стандартизация настроек

**Время MVP:** 4-6 недель

### 2.5. Прогнозирование спроса на маркировку (Time Series)

**Задача:** Предсказать количество КМ, необходимых на период.

**Целевая переменная:** `Количество КМ в день/неделю/месяц`

**Признаки:**

| # | Признак | Тип | Источник |
|---|---------|-----|----------|
| 1 | `historical_demand` | Time Series | COUNT(LFL_MarkingCodeTable) |
| 2 | `day_of_week` | Категориальный | День недели |
| 3 | `month` | Категориальный | Месяц |
| 4 | `is_holiday` | Бинарный | Календарь праздников |
| 5 | `new_suppliers` | Числовой | Количество новых поставщиков MP |
| 6 | `regulation_changes` | Бинарный | Изменения в законодательстве |

**Модели:**
- **Prophet** — для сезонности и трендов
- **ARIMA** — для стационарных рядов
- **LSTM** — для сложных паттернов
- **LightGBM** — для мультивариативного прогноза

**Метрики:**
- MAPE (Mean Absolute Percentage Error)
- SMAPE (Symmetric MAPE)
- RMSE

**Бизнес-эффект:**
- Оптимизация запасов этикеток
- Планирование печати
- Снижение простоев из-за отсутствия КМ

**Время MVP:** 3-4 недели

### 2.6. Кластеризация поставщиков (Clustering)

**Задача:** Разбить поставщиков на группы по качеству КМ.

**Признаки:**

| # | Признак | Тип | Источник |
|---|---------|-----|----------|
| 1 | `total_km_count` | Числовой | COUNT(LFL_MarkingCodeTable) |
| 2 | `problem_rate` | Числовой | COUNT(problematic) / COUNT(total) |
| 3 | `competitor_rate` | Числовой | COUNT(Competitor=Yes) / COUNT(total) |
| 4 | `avg_processing_time` | Числовой | AVG(DurationOperation) |
| 5 | `block_rate` | Числовой | COUNT(Blocked=Yes) / COUNT(total) |

**Модели:**
- **K-Means** — для заданного числа кластеров
- **DBSCAN** — для автоматического определения
- **Hierarchical Clustering** — для иерархии

**Метрики:**
- Silhouette Score
- Davies-Bouldin Index
- Business Metric: Эффективность дифференцированного подхода

**Бизнес-эффект:**
- Дифференцированный подход к поставщикам
- Улучшение условий для лучших
- Ужесточение контроля для проблемных

**Время MVP:** 1-2 недели

### 2.7. NLP для обработки ошибок (Text Classification)

**Задача:** Автоматически классифицировать текстовые описания ошибок.

**Вход:** Текст ошибки из `infolog`

**Выход:**
- Тип ошибки (категория)
- Рекомендация по действию
- Критичность

**Модели:**
- **Fine-tuned BERT** — для классификации
- **RuBERT** — для русскоязычного текста
- **TF-IDF + SVM** — для baseline

**Метрики:**
- F1-score (macro)
- Precision
- Recall

**Бизнес-эффект:**
- Автоматизация обработки обращений
- Чат-бот для операторов
- Снижение нагрузки на поддержку

**Время MVP:** 2-3 недели
